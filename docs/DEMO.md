# Demo：啟動與錄影

用真手機、真車拍，把「拍對 → 判對 → 派對 → 判得公平」整個流程走一遍。

判讀有兩種模式：
- **劇本模式**：分成正常、有新傷、髒車三種，結果照劇本走，錄影不會出包。
- **自動判讀**：真的跑演算法，需要另外裝 OCR 和 YOLO。

手機端的取景框和即時提示（太糊、太暗、直橫、車子位置），在兩種模式下都是真的在運算。

## repo 裡沒有的東西（要自己準備）

官方資料包依競賽規範不得對外提供，下列東西都不進 git（見 `.gitignore`），clone 下來後要在本機產生：

| 東西 | 怎麼來 |
|---|---|
| 官方資料包 | 從比賽寄的連結下載，用 `IRENT_DATA` 指向含 `進行索賠資料/`、`沒有進行索賠/` 的資料夾 |
| 500 組補充照片 | 用 7-Zip 或 Python 解壓（Windows 內建解壓縮會失敗），用 `IRENT_PIC500` 指向 `Hims_Pic500/` |
| 取景框範例圖層 `data/samples/` | 執行 `python scripts\make_samples.py`。沒有也能跑，只是不會出現半透明範例 |
| 自簽憑證 `certs/`、資料庫 `data/demo.sqlite` | `run.ps1` 第一次啟動時自動產生 |

## 啟動

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

- 第一次執行會建立 Python 3.12 環境並安裝套件，之後可以加 `-SkipInstall` 跳過。
- 需要先安裝 [uv](https://github.com/astral-sh/uv)。
- 如果埠被占用，可以加 `-HttpPort 8001 -HttpsPort 8444` 換埠。
- 手機要能連到電腦，所以電腦所在的網路（包括手機熱點）必須設成「私人網路」。

啟動後打開 <http://localhost:8000/>，畫面上有 QR code：

| 誰 | 開哪個網址 | 備註 |
|---|---|---|
| 手機（取景框版） | `https://<電腦IP>:8443/app` | 自簽憑證第一次會跳出警告，選繼續前往，再允許使用相機 |
| 手機（備用） | `http://<電腦IP>:8000/app` | 用手機原生相機拍照上傳，沒有即時取景框 |
| 後台工作台 | `http://localhost:8000/admin` | 轉人工佇列、工單、車輛狀態、事件紀錄 |
| 投影用的現場畫面 | `http://localhost:8000/live` | 手機每拍一張，1–2 秒內就會出現在這裡 |

## 現場拍照的即時分析（環節一）

| 項目 | 怎麼做 |
|---|---|
| 取景框範例圖層 | `overlay.js` 在相機畫面疊一張半透明範例圖；左右方向相反時，可以按「鏡像範例」翻轉 |
| 車輛位置引導 | 手機瀏覽器每 0.3 秒跑一次 TF.js COCO-SSD（上一次還沒算完就跳過），畫出綠框，並提示「往左／往右／抬高／放低／太遠」 |
| 品質檢查 | 拍下的瞬間檢查模糊度（Laplacian）、亮度、直橫 |
| 伺服器逐張回饋 | 先上傳縮圖，伺服器馬上回覆結果；用車牌 OCR、儀表板里程 OCR 當錨點 |
| 軟擋 | 同一個角度連續兩次不合格，可以加註記送出，那一區塊會標成「未驗證」，送人工判斷 |

## 四個錄影劇本

1. **正常還車**：先「取車」建立基準照，再「還車／正常」。照片全部自動放行，車輛回到「可租」。
2. **有新傷**：
   1. 「取車／正常」拍基準照，再「還車／有新傷」。
   2. 第一張車外照的某個區塊差異較大，轉人工；另一個區塊差異中等，送複判。
   3. 後台按「新傷」。
   4. 手機收到通知，附上三張對照圖。
   5. 用戶按「一鍵申訴」，後台選擇「撤銷」或「維持」。
3. **髒車**：
   1. 「還車／髒車」，車內照判定為「髒汙」。
   2. 車輛變成「待清潔」，下一位預約者收到改派通知，同時開出清潔工單。
   3. 上傳清潔完成照，驗收通過後回到「可租」。
4. **取車免責**：上一位用戶還車正常；下一位用戶取車時拍到髒車。手機顯示「已登記為取車前既有狀況，不會算在您身上」，同時自動開出清潔工單。
